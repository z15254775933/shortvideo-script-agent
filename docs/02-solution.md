# 方案与技术取舍

状态：0.2.0 交付版本。原 A01—A07、C01 保留，新增 A08—A10 创作模式验证；最新实现与失败修正见 `docs/08-improvements.md`，首次交付复核快照见 `docs/07-final-verification.md`。

## 1. 当前实现

采用 Python 标准库、原生 Chat Completions HTTP 接入，无 Agent 框架和第三方运行时依赖。项目元数据及可选安装入口由 `pyproject.toml` 描述；已验证的运行路径是仓库根目录的 `python -m src.shortvideo_agent`，本阶段未验证打包安装。

| 文件 | 当前职责 |
| --- | --- |
| `src/shortvideo_agent/cli.py` | 输入、连接、Schema、独立工具和 `run` 入口，保存结果及逐事件日志 |
| `config.py` | `.env` 与进程环境变量、官方主机检查、配置及执行上限默认值 |
| `contracts.py` | 六种版本 1 数据契约、结构校验和缺失字段识别 |
| `io_utils.py` | 严格读取 JSON、脱敏输出、避免覆盖已有文件 |
| `materials.py` | 素材和规则加载、素材／事实／规则 ID 唯一性检查 |
| `models.py` | 真实 DeepSeek 请求、响应归一化、错误处理、离线固定响应诊断 |
| `tools.py` | 素材检索、时长估算、品牌与事实检查、脚本指纹、工具定义与上下文绑定的调用分发 |
| `agent.py` | 模型选择动作的有界循环、运行记录、修订管理、最终证据校验和可编辑脚本渲染 |
| `mock.py` | 明确标记的离线预设动作，覆盖程序执行流程，不证明模型效果 |
| `comparison.py` | 共享已保存对话前缀的真实单步检索观察对照，明确区分重放与新调用 |
| `evaluation.py` | 离线验收实际产物、重算检查、核对路径与指纹、生成机器报告 |
| `grounding.py` | 创作指导、逐字段独立审核、审核预算／缓存、工作流承诺检查及离线审核重放 |

选择标准库是为了减少安装成本并明确展示模型、工具和执行循环各自的职责。代价是需要自行维护请求、校验和运行边界；当前自实现校验器仅覆盖实际使用的 Schema 关键字。

## 2. 数据约定

所有业务文档携带 `schema_version: 1`。Schema 的唯一代码来源是 `contracts.py`，用 CLI 导出，不维护两套手写字段定义。

| 契约 | 主要字段与约束 |
| --- | --- |
| `brief` | `topic`、`audience`、`platform`、`target_duration_seconds`、`style`；缺失项允许进入补充流程；提供时必须类型正确；目标时长为有限正数。可选 `product_id` 标明产品范围 |
| `materials` | `synthetic`、`description`、`materials[]`；每个素材有 `material_id`、`product_id`、`tags`、`facts[]`；事实有 `fact_id`、`statement`、`qualifiers` |
| `rules` | `synthetic`、`product_id`、`rules[]`；规则含 `rule_id`、`kind`、`value`、`description`；类型为禁用表述或必须声明 |
| `script` | `revision`、`title`、`scenes[]`、`estimated_total_seconds`；每镜含 `scene_id`、`visual`、`voiceover`、`subtitle`、停顿和画面时长、估时及 `citations[]` |
| `result` | `run_id`、`mode`、业务 `status`、`reason`、原始需求、脚本、`checks`、风险和补充请求 |
| `trace` | 输入、模式、模型、起始时间、次数上限、事件序列、最终状态、结束原因和调用计数 |

引用项必须包含 `material_id`、`fact_id` 和具体 `claim`。合法 ID 仅是结构前提，产品表述是否得到事实支持由第三步检查工具负责。

脚本修改后由程序分配递增的 `revision`，忽略模型任意填写的修订号；检查记录同时保存 `script_revision` 和 `script_sha256`。规范化 JSON 字段顺序后对修订号、正文、引用、停顿和画面预算做 SHA-256，排除两个由工具计算的估时字段。每次实质改稿后清除旧检查，同一内容再次检查不产生新修订。最终成功必须绑定当前版本及当前需求目标。

候选脚本的分镜估时和总估时允许为 `null`，表示尚未估算。第三步时长工具根据文本与时长参数重新计算，忽略模型填入的估时；规则工具已检查每镜至少有旁白或字幕、分镜编号唯一等约束。

Trace 事件包含步骤、时间、动作、模型参数、实际稿件修订和观察结果；原生响应中的工具调用 ID 将动作与结果关联。`reason_summary` 是模型提供的简短公开动作说明，不是内部思维过程。已实现完整 Trace 和即时写入的事件日志；模型响应只保存可见内容、工具调用及用量。

## 3. 模型接入

当前使用 `https://api.deepseek.com` 和 `deepseek-flash`，配置支持切换账户可用模型。基于 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/) 实现请求格式。

请求关闭思考模式、关闭流式输出；提供工具时使用模型自动选择。响应保留可见文本、工具调用 ID、名称及原始参数字符串、结束原因和用量；不保留内部推理字段。工具参数的解析及业务合法性检查由后续执行层负责。

适配器不执行工具，不包含自动重试。截断或无法识别的响应不能作为成功结果；HTTP 错误只返回状态码等必要信息，避免输出原始响应、请求头或密钥。真实模式不会静默切换 Mock。

`OfflineMockClient` 仅固定回答 `OK`，用来在无网络和无密钥时检查 CLI 诊断流程。它尚未模拟业务路径，也不构成 ReAct 决策证据。

## 4. Agent 执行循环

三个业务工具使用原生工具定义提供给 DeepSeek，另加结构化的 `finish_task` 终止动作。模型自行决定检索、提交或修改脚本、检查、补充或结束。执行层没有写死检索无结果后的动作，也不在检查不通过时替模型改稿。

模型在估时或规则检查参数中提交完整脚本，执行层将它注册为当前稿，再把实际结果返回模型。纯文本输出不构成完成，必须使用终止动作。无效参数、未知工具或无依据的成功请求作为结构化观察返回模型，仍计入调用上限。终止动作必须单独调用，避免模型在同批结果产生前宣告成功。

成功需同时满足关键输入齐全、当前稿件存在、引用经过真实检索、当前版本两项检查均通过且目标时长一致。程序用实际时长结果填充最终分镜与总时长，不相信模型提供的估时或“已经通过”的文字。

默认最多模型请求 10 次、全部工具调用 16 次（包含终止和无效调用）、单请求超时 30 秒、每次输出 4096 tokens，均可配置。上限在每次模型请求和批次内每个工具调用前核对；达到上限返回明确未完成。边界已通过离线测试及保存的 Mock 上限示例验证；真实路径也记录实际次数。

已完成 A01—A07 的实际样本验收，并通过共享前缀的 C01 单步对照验证检索返回变化后的动作差异，证据见 `docs/03-evaluation.md` 和 `examples/phase05/acceptance.actual.json`。可用 `evaluate` 命令离线重算与审计；预设初稿和固定响应均由开发 AI 助手编写，不能将其或单步对照误标为完整模型运行。

## 5. 三个业务工具的实现与取舍

### 素材检索

对查询和素材文本做全半角规范化，使用中文二字片段、英文／数字词以及完整短语匹配计分；分数相同时按素材 ID 排序。检索范围固定为当前需求的产品，返回原始事实及限定，数量默认 5 条、最多 10 条。无结果返回空列表，工具不会自己改查询。

采用本地确定性检索是为了可复现、可控制无素材场景。它不具备语义检索能力，查询包含“自动字幕”而命中“支持字幕”也不能推导出自动识别功能。

### 时长估算

项目默认假设：旁白中文等非英文字符每秒 4 个、英文每秒 2.5 个单词；字幕每秒 5 个字符或 3 个英文单词；数字逐位计算；旁白每个标点增加 0.2 秒。它们是项目估算参数，不是行业标准或实际成片测量。

每镜时长为：`向上取整到0.1秒(max(旁白时长, 字幕阅读时长, min_visual_seconds) + pause_seconds)`。先逐镜取整，再以十进制求和并与目标的原始数值比较；旁白与字幕同时呈现，不把两者相加。忽略脚本自报的估时，输入脚本也不会被修改。

语速和目标时长不在模型可选工具参数中，避免通过放宽目标或提高语速“修复”超时。必要画面占用仍是脚本预算，无法由此证明成片的节奏或可读性。

### 品牌与事实检查

严格模式使用保守、可解释的字面政策：逐条核对素材 ID、事实 ID、产品范围、原句与全部限定，且引文必须出现在对应分镜。至少要有一条已核验的产品事实。额外检查标题、画面、旁白及字幕，未被已核验事实或公开连接短语覆盖的内容一律返回 `unverified_text`。

严格模式的连接短语政策随检索和检查结果返回。安全改写也可能被拦截。0.2.0 新增创作模式：保留原句、限定、引用、品牌及版本检查，允许自由文案，再用独立对话审核所有可见字段；已观察到的工作流承诺另加确定性检查。该模式默认为真实运行使用，仍可能语义误判，不验证素材本身真实性。

审核器每次只执行一次固定审核任务，没有 Agent 决策循环。默认另限 4 次请求，失败也计数；相同审核输入可缓存，输入改变即失效。完整响应留在 Trace，反馈给业务 Agent 的是检查问题和摘要。离线评审只重放存档审核、核对指纹与原始响应，不声称离线重新完成了语义判断。

品牌规则支持禁用表述和必须声明；需要的声明同时受到事实与文案政策约束，若给定规则与可用资料无法同时满足，应由后续模型说明未完成原因。未提供额外品牌规则时，事实检查仍然执行。

比较会规范化大小写、全半角及部分排版标点，保留数值分隔符和百分号等，避免小数点等符号丢失后错误支持另一数值。

### 工具调用分发

`ToolRegistry` 将产品、目标时长和素材绑定到当前需求，校验模型参数后调用工具。工具执行错误与业务检查不通过分开表示。显式故障注入返回可识别标记，默认关闭；调用分发器本身没有恢复、自动重试或业务决策循环。Agent 中的真实模型根据这些返回结果选择后续动作。
