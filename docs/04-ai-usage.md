# AI 使用说明与参与记录

日期：2026-10-28。记录范围：当前会话、项目文件、实际运行产物及交付过程。

本项目使用 AI 辅助完成需求整理、方案、代码、测试、样例及文档。开发阶段的本地命令和真实模型测试也由 AI 助手执行。以下说明不把这些工作归写为提交者亲手实现或独立验证。

## 1. 开发辅助与运行时模型

| 对象 | 实际用途 | 证据边界 |
| --- | --- | --- |
| 当前 Codex 会话中的 AI 开发助手 | 分解需求，提出技术方案，编写和修改本地代码、测试、合成资料及文档，运行本地验证 | 属于开发辅助，不等同于项目运行时 Agent |
| DeepSeek `deepseek-flash` | 运行时选择业务工具、观察结果、生成或修改脚本、请求补充或结束 | 完整真实记录为 `examples/phase04/`、`examples/phase05/` 中 `mode: real` 的 9 次运行 |
| 真实模型单步对照 | 在共享的既有对话前缀后，观察两种实际检索结果并各新增一次决策 | `retrieval-comparison/` 的 2 次新增请求，不计为 2 次完整 Agent 运行 |
| 离线 Mock 与预设模型响应 | 验证 CLI、错误路径、版本绑定、执行上限等程序行为 | 固定流程不能证明真实模型决策效果；输出和测试中均明确区分 |

模型名称及行为描述对应已保存运行，不承诺该别名以后始终指向同一后端版本。

如果提交者后续亲自复核或修改，可在本节追加实际日期、文件、修改理由、运行命令和结果；当前记录不预填这些经历。

## 4. AI 产出的实际修正与验证

以下工作均由开发 AI 助手执行，并保留可检查的代码或结果：

1. 事实检查没有停留在来源 ID 是否存在：增加原句、限定、产品范围及整稿额外表述检查，保留小数点、百分号等影响数值含义的符号。代价是会拦截部分安全改写。
2. 将模型自报估时改为工具重算，使用逐镜向上取整与十进制求和；最终时长取实际工具结果。
3. 由程序管理稿件修订并在改稿后清除旧检查，防止新版本复用旧通过结果。相关执行边界由预设响应测试验证。
4. 对真实运行执行离线重算与日志审计；同版指纹、实际工具事件、引用来源、调用数和可编辑文本均进行核对。
5. 一次普通请求下，模型在审稿前主动删除了无依据数字。该结果被保留；随后用明确要求先审稿的独立输入，验证工具指出问题后模型改稿的链路，没有将前一条记录改写成后一种过程。

以上是项目中的实际迭代，不是提交者个人修改的替代声明。

## 5. 验证结果与责任边界

当前保存样本的 A01—A07、C01 共 8 项审计通过，81 项离线回归通过。完整口径、实际结果和复现命令见 `docs/03-evaluation.md`。预设响应测试覆盖程序行为；模型动态决策效果以真实 Trace 和单独标记的对照记录为依据。

未验证的部分包括任意自由改写的语义核验、真实配音／成片时长、其他平台或 Python 版本、模型统计成功率，以及打包安装。提交者仍需自行理解设计取舍、判断适用边界，并确认最终提交内容。

真实凭据仅用于授权的 DeepSeek 官方接口，保存在本地被忽略的 `.env`；模板与样例不包含真实密钥，输出不记录模型内部思维过程。
