# 工程复盘与后续改进

当前为 0.2.0。第 1—6 节保留原核心链路的取舍与时间记录，本轮学习证据和修正在第 7 节；均为开发 AI 的工程记录，不代写本人经历。

本复盘归纳项目实际实现和运行证据，由 AI 助手辅助整理。文中的工程认识不自动代表提交者已经形成的个人学习经历；个人参与与独立验证的当前记录见 `docs/04-ai-usage.md`。

## 1. 最主要的工程难点：让完成状态有可靠证据

生成一段脚本并不等于完成任务。模型可能在时长检查后修改字幕，或在规则检查后调整画面预算；即使之前两项检查都通过，也未必对应最后交付的稿件。

解决方法是由程序管理当前稿件：对修订、正文、引用、停顿和画面预算计算指纹，忽略模型自报估时；实质改稿后递增修订并清除旧检查。只有当前版本的两项实际检查通过、来源已经检索且输入齐全，`finish_task(success)` 才被接受。

这既保留模型对业务动作的选择，也让成功状态具有明确的程序边界。`tests/test_agent.py` 验证了旧检查失效、提前结束被拒、同一批次不能先猜测检查通过等情况。

## 2. 事实可信与文案自由的取舍

素材只有“支持字幕”时，引用 P01 并不能支持“效率提升80%”。因此工具核对原句、完整限定和产品范围，并扫描标题、画面、旁白及字幕中没有依据的额外表述。

在当前时间范围内，采用原句加有限连接短语政策，使检查可以离线复现。它的代价在真实运行中可见：正常生成稿需要多轮处理政策外文字，工具故障样本共使用 9 轮，接近默认 10 轮上限。安全的自由改写也可能被拦截。

这是一项明确的产品限制，不能将它描述成通用语义理解。后续应先建立覆盖限定、数字和同义表达的评测集，再考虑语义核验，不能仅凭文案更自然就放松事实约束。

## 3. 评估方法带来的认识

实际工程可以支持以下认识：

- Mock 和真实模型验证解决不同问题。预设响应适合检验计数、错误和状态边界；真实 Trace 才能展示观察结果后的模型选择。
- 规则不通过与工具故障不同。前者是执行正常但需要改稿，后者必须如实记录错误，由模型决定后续动作。
- 数字与限定属于事实含义。忽略小数点、百分号或“仅限桌面版”等限制，会把一个有来源的描述变成另一个没有依据的结论。
- “一轮调用多个工具”不等于模型已观察到所有结果。因此终止动作必须单独提交，工具上限也必须在批次内部逐个检查。
- 样本通过不能直接解释为总体成功率。当前只覆盖保存的合成场景，尚无跨模型、跨系统或重复抽样统计。

## 4. 实际验证中暴露的问题

| 问题 | 实际表现 | 处理及剩余边界 |
| --- | --- | --- |
| 模型字段类型不符 | 工具故障运行中，首个估时请求把各镜 `min_visual_seconds` 设为 `null`，而契约要求数字 | 返回结构化参数错误，模型修正为数值后重新调用；仍消耗一次调用预算 |
| 保守政策误拦 | 正常稿中的部分标题／连接文字需要多次修正 | 反馈位置并重新检查；文案表达空间仍有限 |
| 尚未产生想观察的失败链路 | 模型直接删去初稿效果数字，没有先让工具指出问题 | 保留原记录，另以“先审稿”输入验证观察后修改；没有篡改日志 |
| 测试环境权限 | 初期测试无法读写系统临时目录 | 在允许临时目录访问的环境重跑通过；没有把该权限问题算作业务恢复效果 |
| 估时与成片有差异 | 采用固定语速、阅读速度、画面占用及停顿 | 明示为估算，未宣称测过真人配音或真实视频 |

## 6. 后续优先级

1. 提交者自行复核至少一条成功路径和一条需要补充的路径，说明模型动作与程序约束各自的职责，并如实追加个人操作记录。
2. 在已完成的无密钥环境复核及公开仓库基础上，以真实 Git 记录核对最终 SHA；当前交付入口见 `docs/07-final-verification.md`。
3. 扩充可用素材及负例，区分规则误拦与实际无依据表述，评估受约束的同义改写支持。
4. 使用真实配音校准估时误差，进行多次模型运行和成本／调用轮数统计，再决定是否需要更复杂的运行平台。

这份复盘没有声称上述后续工作已经完成，也未代填个人学习感受。

## 7. 0.2.0：表达自由增加后，审核本身也需要反例

原字面白名单把安全文案也拦住，实际脚本容易模板化。本轮在保留原句、限定、引用及版本约束的前提下，增加自由创作与独立模型审核，得到可拍摄的抖音情境稿和区分已知／未知的 B站解释稿。

新增审核实际暴露了两种不同问题：一次响应多返回原文导致契约不匹配；另一次审核放过“无需重剪”类工作流推论。前者通过严格核对可选回显处理；后者保留为真实漏检反例，并增加有限短语的确定性来源检查，再重新生成与验证。不能把“加了另一个模型调用”当成事实问题已经解决。

完整审核留在 Trace、给 Agent 发送摘要有助于减少重复上下文，但单次试跑内容及轮数不同，而且其中存在漏检，因此不把一次 token 差异写成成本优化率。

本轮测试包含漏审、伪造证据、审核失败计数、预算和缓存边界、原始审核响应篡改及真实漏检回归。当前是 11 项主验收和 102 项离线测试；原记录、失败边界和成本分项见 `docs/08-improvements.md`。下一步应优先扩充盲测反例和真实配音校准，继续检验审核误判与估时误差。
